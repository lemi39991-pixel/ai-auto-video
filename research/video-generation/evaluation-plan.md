# 视频生成候选样片验证计划

本计划把 GitHub 文档中的能力转化为可观察结果。所有测试目前均为待执行；本轮调研没有生成样片、消耗付费接口或发布视频。

## 1 验证目标

第一轮优先验证 MoneyPrinterTurbo 能否在本机无 GPU 配置下生成可用中文短视频，并通过程序提交任务、获得结果。其他候选只有在内容需求或第一候选的缺口明确后再增加。

要回答的问题包括：文案是否保留、画面是否相关、中文是否清楚、制作耗时和费用多少、失败是否可定位，以及能否接入我们的后台。

## 2 统一测试输入

| 编号 | 内容 | 固定输入 | 观察重点 |
| --- | --- | --- | --- |
| A | 通用知识讲解 | 一份约 30～60 秒的中文脚本，相同主题关键词 | 素材相关性、配音、字幕 |
| B | 软件操作教程 | 同一份脚本、三段自有录屏、两张截图及明确顺序 | 自有素材使用、镜头顺序、实际操作是否讲清楚 |
| C | 中文混合术语 | 含 AI、API、数字、日期与产品名称的短脚本 | 读音、汉字字体、换行和字幕时序 |
| D | 已有视频解说 | 一段许可明确的自有视频及人工整理的事实表 | 视频理解、解说事实、时间轴；主要用于 NarratoAI |

同一路线尽量使用相同脚本、声音、分辨率、素材和机器。无法统一的模型与配音服务单独记录。A 与 D 不是相同任务，分别评价，避免跨路线给一个笼统总分。

第一轮不启用 AI 动态画面生成。需要比较云端生成路线时，新增独立测试组，记录模型、生成片段数量、失败次数和实际费用。

## 3 执行步骤

1. 记录项目 URL、分支和完整提交 SHA，保存脱敏配置摘要。
2. 检查 README、依赖、许可证与本项目相关指令；使用独立环境安装。
3. 验证字体、FFmpeg、配音和模型访问，确认使用 CPU 配置。
4. 用固定脚本完成一条最小样片，再执行该路线适用的测试输入。
5. 检查程序接口是否能提交、查询和取得成片，不依赖人工从目录猜测输出文件。
6. 对选中的一条样片重复一次，区分首次下载开销与后续生成耗时。
7. 模拟一次可控失败，例如无效素材路径，确认不会误报成功，记录能否复用已完成结果。
8. 完成人工审阅，保留成片路径、问题截图和改进建议。

此阶段只生成和本地预览，发布接入在整体实施方案的对应阶段单独验证。

## 5 通过条件

以下是本项目拟定的试验标准，不是上游性能承诺。

| 维度 | 进入集成的条件 |
| --- | --- |
| 内容 | 固定文案中的关键事实没有被擅自改写；画面可解释主要内容 |
| 中文 | 无缺字方框，关键术语可理解，字幕不遮住关键操作 |
| 声画 | 无意外黑屏或长静默，配音清楚，字幕没有明显持续错位 |
| 素材控制 | 教程路线可以使用指定素材和合理顺序；不支持时明确列出补充开发量 |
| 无 GPU | 所选配置在目标机器上实际完成；记录云端依赖，不隐含本地模型要求 |
| 程序调用 | 有可重复的提交和获取结果方法，错误能被上层识别 |
| 成本 | 用量可追溯，未知费用明确；结合预算决定可接受产量 |
| 可恢复性 | 失败不标成成功；若只能整条重做，记录额外成本并评估是否接受 |

不预设统一的“几分钟一条”门槛。先测出目标机器的耗时，再结合每日计划产量和人工修改时间制定要求。

## 6 选型决策

- MoneyPrinterTurbo 的 A、B、C 测试达到目标：先接入整体后台，固定该版本。
- 通用讲解可用但教程素材控制不足：保留其配音与合成能力，评估增加自有分镜处理。
- 内容以已有视频解说为主：补测 NarratoAI 的 D 组，和当前方案分别评估。
- 需要更细的 Python 编辑控制：补测 ShortGPT，先解决依赖和中文流程再比较成本。
- 以后需要英文库存素材视频：再验证 short-video-maker；中文改造另估工作量。
- 需要生成原创画面：单独验证云端生成和素材复用路径，参考 ai-shorts-generator。

最终记录采用理由、未解决问题和切换成本，不用项目热度代替样片判断。
