# 国内抖音首条带货视频试运行步骤

更新日期：2026 年 10 月 14 日。状态：待执行。

首轮目标是在一个国内抖音账号上，从一个用户批准的商品生成一条中文竖屏视频，用户判断并确认后，由系统发布、正确关联商品并保存结果。订单和佣金随后按实际发生与结算记录。完成发布不代表已经产生收入。

用户负责账号方向、选品、选题和内容判断，执行分工见[盈利方案](monetization-plan.md)。手机 Agent 接入、海外平台和完整效果看板后置，首轮使用电脑上的最小任务入口与本地预览。

## 一 准备目标账号

先确认使用现有账号还是新建账号，检查是否有商品分享权限、能否选择推广商品、发布页是否支持关联该商品，以及收款账户是否可用。具体条件以该账号的当前申请页为准。

抖音官方指南介绍了商品橱窗、商品分享权限与收款账户的开通流程。[官方新手指南](https://school.jinritemai.com/doudian/web/course-series/cHSMH4XjcRvj/cHSMH4XjcRvjlHVD3jbxA8wx)

首次登录和需要本人完成的验证由用户处理，登录文件本地保存，不进入 Git 或调研文档。尚未开通权限时继续做本地生成验证，发布与商品关联步骤保持待处理，不用普通视频成功替代带货成功。

## 二 确定第一条内容

| 输入 | 谁提供或决定 | 通过条件 |
| --- | --- | --- |
| 账号方向与观众 | 用户 | 明确给谁看、解决什么问题，不预设固定品类 |
| 商品链接与可推广标识 | 用户批准，系统核对 | 目标账号可以推广，标识可核对 |
| 一个内容角度 | 系统提议，用户判断 | 与商品真实用途相符，关键事实有依据 |
| 商品展示素材 | 系统取得 | 来源和许可明确，能展示必要画面 |
| 脚本 | 系统生成，用户判断 | 表述准确，不虚构实测或使用体验 |
| 声音与模板 | 系统使用已验证配置 | 中文可理解，字幕与关键画面不冲突 |

优先选资料完整、素材可用、用途能解释清楚的商品。缺少可使用素材时，系统更换角度或候选商品，不把录制和剪辑作为用户的日常任务。商家素材需确认用途和许可，不能将他人的视频下载后直接视为可用素材。

## 三 固定和验证执行环境

MoneyPrinterTurbo 与发布组件各自使用独立环境并固定完整提交 SHA。开发细则中的 Python 版本和依赖需随固定版本复核，不能直接复用不满足要求的系统 Python。

检查 FFmpeg、ffprobe、中文字体、磁盘空间及模型和配音服务连接。模型与配音先选实际可接通的一套，密钥在本地单独配置。测试预算按用户配置执行，首轮关闭云端生图、生视频和付费音乐。

启动前核查发布组件的上传与商品关联能力。仅 README 标注支持抖音上传不算挂商品已验证；需要定位实际输入、执行路径和结果核对方法。缺少商品关联功能时，先补充适配或验证另一条可用路径，并记录工作量。

## 四 执行首条任务

| 顺序 | 系统执行 | 用户动作 | 完成证据 |
| --- | --- | --- | --- |
| 1 | 保存商品、方向与资料，校验素材 | 判断商品与内容角度 | 本地任务与批准记录 |
| 2 | 生成脚本和画面安排 | 接受、拒绝或提出修改意见 | 脚本版本与来源 |
| 3 | 配音、字幕、时间轴与合成 | 无需手动制作 | 音频、字幕、视频和费用记录 |
| 4 | 自动检查，展示成片与发布清单 | 判断并确认具体内容与商品 | 文件摘要、目标账号、商品标识和确认记录 |
| 5 | 校验登录、商品状态及确认，提交发布 | 仅处理必须本人完成的验证 | 执行记录、平台结果和关联证据 |
| 6 | 核对公开状态及商品购买入口 | 系统无法核对时确认远端事实 | 作品标识、观察时间、正确商品关联 |
| 7 | 取得可用的点击、订单与佣金数据 | 无需日常手填；偶发导入另记 | 有来源和观察时间的数据记录 |

确认后的任何实质修改使旧确认失效。上传超时或程序在提交中退出，进入待核对，禁止直接重发。推广商品失效或价格变化导致文案不准确时暂停，重新制作和确认。

## 五 分别验收三个结果

| 结果 | 条件 | 尚不证明什么 |
| --- | --- | --- |
| 制作闭环 | 中文视频、字幕和素材检查通过，用户接受成片 | 不证明账号能带货或内容能成交 |
| 发布闭环 | 自动发布公开可见，关联正确商品，结果可核对 | 不证明已经获得订单与佣金 |
| 盈利观察 | 有真实归因、订单状态和结算证据，包含成本与退款调整 | 一笔收入不证明稳定盈利 |

真实订单可能不会在第一次发布后出现，不以自行购买或虚构数据填充验收记录。没有订单时如实记录观察结果，用户决定是否调整选品与内容。

仅导出、人工上传或人工逐条挂商品可以用于排查，但不算自动发布验收通过。自动获取数据不可用时明确标记缺口，不把未知填零；若日常需要大量手工录入，则仍未符合目标。

## 六 首条记录和扩展条件

首条记录包含目标账号的内部标识、商品标识、来源和素材使用条件、组件版本、成片摘要、确认版本、制作费用、阶段耗时、人工决策分钟、异常处理分钟、发布证据和后续结算。账号凭据和个人信息留在本地运行目录。

制作和发布均通过后，再执行三条不同内容和十条连续任务，观察读音、画面准确性、重启恢复、去重与人工介入原因。达到质量与自动化目标后才按[首月计划](monetization-plan.md)扩展到 20～30 条。

当前首条任务需要先确定目标账号的带货状态、账号方向和首个商品。条件未齐时推进环境与本地样片工作，保持真实发布步骤待处理，不提前宣称闭环已经跑通。
