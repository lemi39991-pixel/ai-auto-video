# AI 短视频第一版开发细则

更新日期：2026 年 10 月 14 日。状态：待实施。

第一版先交付一个单账号、有人审核的制作工具，让用户用真实素材完成中文竖屏视频，确认后导出发布包。自动上传通过独立验收后启用。本文把[实施方案](implementation-plan.md)拆成开发任务、数据约定和验收门槛；以下接口、配置与阈值是本项目设计，需随样片结果调整。

## 一 交付范围和操作流程

基础版集中在三个页面，目标产量先按每天 1～2 条、每条 30～60 秒设计。

| 页面 | 第一版操作 | 必须看见的信息 |
| --- | --- | --- |
| 任务列表 | 新建、打开、取消、重试 | 当前步骤、缺失项、最近错误、累计费用 |
| 视频工作台 | 编辑脚本、选择素材片段、试听、生成、预览、确认、导出 | 每段文案与画面对应关系、版本、检查结果 |
| 设置 | 内容方向、声音、模板、预算、组件连接；上传启用后管理账号 | 连接状态、已验证能力、需要用户处理的问题 |

选题库、独立发布队列、多模板和效果看板后置。基础版在任务详情中记录手动发布链接和数据，不单独开发复杂报表。

用户完成一次任务的顺序为：输入主题和资料 → 生成或粘贴脚本 → 编辑分段与素材 → 试听并确认脚本 → 制作 → 预览修改 → 确认发布内容 → 导出。自动上传启用后，在最后一步增加“上传到已确认账号”。脚本确认用于控制付费制作，成片确认用于控制导出和发布，两者分别记录。

## 二 样片验证和组件选择

### 2.1 先做三个固定输入

沿用[样片验证计划](../research/video-generation/evaluation-plan.md)的 A、B、C 输入。先完成三条，再扩展到十条实际内容；同时选择三条有代表性的内容按当前手工流程制作，作为耗时比较的基线。

| 样片 | 固定输入 | 要回答的问题 |
| --- | --- | --- |
| 通用讲解 | 已确认脚本、自有图片和视频 | 中文配音、字幕、合成是否可用 |
| 操作教程 | 三段录屏、两张截图、明确操作顺序 | 讲到具体步骤时能否展示正确画面 |
| 混合术语 | 产品名、数字、日期、AI 和 API | 读音、断句和字幕是否可理解 |

固定上游完整提交 SHA、依赖版本、声音、字体和输出参数。记录首次准备时间、后续制作时间、人工修改分钟、实际账单、内存峰值和磁盘增长。首轮关闭云端生图、生视频和付费音乐，准备素材不计入机器渲染耗时，但计入人工总耗时。

### 2.2 决定生成组件承担多少工作

MoneyPrinterTurbo 当前参数支持固定脚本、本地素材和顺序拼接，但默认使用随机拼接；公开素材对象没有直接表达逐段口播对应的源片段起止时间。本项目应通过实测决定是否补充编排。[参数定义](https://github.com/harry0703/MoneyPrinterTurbo/blob/main/app/models/schema.py)

| 测试结果 | 实施选择 |
| --- | --- |
| 整条生成可控，教程画面同步合格 | 通过适配层调用整条生成，保存完整输入和产物 |
| 配音字幕可用，镜头顺序或时长不满足要求 | 复用已验证能力，本项目按分段时间轴合成 |
| 中文或程序调用不稳定 | 先定位问题，再验证一个替代组件；不同时集成多套引擎 |

三条样片进入集成的条件：关键事实不被改写，必要字幕存在，关键操作完整可见，程序能关联输入与输出，费用和失败可追溯。十条样片中至少八条经一次预览及小修改后可发布，作为初始试运行目标；这不是上游承诺。未达标时先解决共同问题或收窄视频形式，再开发扩展功能。

## 三 分镜和时间轴

### 3.1 每段脚本的数据

第一版建议一条视频分成 4～6 段。开头、问题、操作、结果和限制可作为模板，用户可以删改，不强制每条采用同样结构。

| 字段 | 含义 |
| --- | --- |
| segment_id 和 order | 段落身份及展示顺序 |
| narration 和 speech_text | 展示文案与配音文本；读音修正单独保存 |
| source_refs | 支持关键事实的资料标识 |
| asset_id 和 source_in_ms/source_out_ms | 选定素材及源片段范围，时间使用整数毫秒 |
| fit_mode | 完整显示或裁剪填满 |
| key_visual | 必须看清的操作或结果，供预览检查 |
| audio_artifact_id 和 audio_duration_ms | 配音产物及实测时长 |
| timeline_start_ms/timeline_end_ms | 按配音长度累计得到的成片时间 |

画面与口播按段绑定。例如“点击导出”这段绑定点击按钮的录屏，下一段“查看结果”绑定结果画面。横屏软件录屏默认完整显示并放入竖屏背景，用户选择裁剪时预览裁剪范围；不能默认裁掉侧边菜单或操作按钮。

### 3.2 制作顺序

1. 校验资料、脚本和素材范围，缺失项回到待处理。
2. 生成配音并测量实际长度。整条引擎必须证明其时间轴可用；独立分段合成则逐段生成配音。
3. 计算每段在成片中的起止时间，将字幕时间平移到对应位置。
4. 图片保持到该段结束；录屏按指定区间使用。需要适配长度时先提示用户，禁止静默加速关键操作。
5. 源视频短于配音时，可由用户选择在操作结束后保持最后一帧、补充结果截图或缩短脚本；素材不足不循环重复关键操作。
6. 合成音轨、画面、字幕与模板，执行自动检查，生成预览版本。

独立合成路线首版使用直接切换，不加入复杂转场。短段配音可能有明显停顿，需要在教程样片中检查自然度；不能为了便于缓存而牺牲口播质量。

目标输出先设为 MP4、H.264、AAC、1080×1920、30 fps，这是本项目初始导出配置。平台兼容性由上传验证决定，性能不足时单独评估较低分辨率。封面先提供一套模板：标题加自有截图，尺寸随实际上传能力确定。

## 四 配音和字幕

第一轮优先验证 Edge TTS 与上游 `edge` 字幕组合。它是否适用于所选调用路径和分段合成，需要一并验证；若适配成本高，可以先保留整条生成路径。

| 路线 | 使用条件 | 需要补充的工作 |
| --- | --- | --- |
| 上游配音加时间戳字幕 | 能稳定取得音频和字幕产物 | 术语修正、段落时间平移、字幕检查 |
| 外部付费配音加供应商时间戳 | 实际接口提供可用时间戳 | 将时间戳转成统一字幕格式，验证中文断句 |
| 外部配音加转录或强制对齐 | 时间戳不可得且该路线已实测 | 增加 CPU 耗时或云端费用，校对术语 |

上游自定义音频没有配音时间轴，默认 `edge` 字幕会跳过生成；不能只替换音频服务就假定字幕仍然可用。[音频与字幕实现](https://github.com/harry0703/MoneyPrinterTurbo/blob/main/app/services/task.py)

成本表中的 Qwen3 TTS 继续作为预算参照，实际采用的供应商与字幕路线确定后再更新单条成本。不得自动启用未验证的转录服务或付费备选。

术语修正保存“API”与实际配音读法的对应关系，字幕保留正常书写。修改配音读法也生成新版本，触发对应音频和后续产物失效。第一版支持改脚本后重新制作；逐字拖动字幕时间轴后置。

## 五 任务执行和产物复用

### 5.1 单机执行约定

FastAPI 处理编辑和查询，一个独立工作进程领取持久化任务。视频制作与上传均保持单任务执行，初版避免浏览器和合成同时争用资源。网页关闭不会取消后台任务。

任务领取在短事务中完成：检查待执行状态和可执行时间，写入执行者、尝试编号与租约期限，然后提交事务。网络调用和合成期间不持有数据库事务。初始心跳间隔设为 10 秒，租约为 60 秒；过期后进入恢复检查，不能仅因心跳超时就启动第二次制作。

恢复时先确认本地子进程或组件任务是否仍运行。仍在运行则继续监控；查询结果不明则待核对；确定停止且产物无效时才允许重试。新执行者接管后，旧尝试不能覆盖新状态。所有长调用设置独立超时，保留子进程或上游任务标识。

### 5.2 阶段与产物

| 阶段 | 成功时保存 | 重试或修改规则 |
| --- | --- | --- |
| 脚本 | 脚本版本、资料引用、模型用量 | 用户编辑后保存新版本 |
| 配音 | 音频、实测时长、供应商与声音参数 | 文案和声音参数不变才可复用 |
| 字幕 | 字幕文件、来源、有效条目数 | 配音变化后重新生成或对齐 |
| 时间轴 | 每段素材范围、音频长度、展示参数 | 替换素材后重新校验与计算 |
| 合成 | 视频、渲染参数、文件摘要 | 写临时文件，验证后移入版本目录 |
| 检查 | 硬错误、提示项、人工处理记录 | 硬错误阻止进入待确认 |
| 导出 | 确认编号、文件清单及摘要 | 相同确认请求复用既有导出包 |

缓存键包含文本、素材摘要及裁剪范围、声音参数、模板版本、引擎版本等实际影响产物的输入。更换标题只重新制作封面或发布包，更换视频字幕样式重做合成；旧成片保持可查看，但不能代表最新草稿。

产物保存在 `runtime/projects/<project_id>/versions/<version_id>/`，确认版本使用不可变文件。数据库保存相对路径和 SHA-256，应用通过文件标识访问，不接受任意服务器路径。自动清理先只处理未引用的临时文件，确认成片和发布证据必须明确保留。

### 5.3 重试和取消

临时连接失败最多自动重试两次，初始退避为 5 秒和 20 秒；配音或模型调用结果不明时先核对用量与任务结果，不能把可能已收费的请求直接当作免费失败。缺素材、配置错误、登录失效进入待处理，不自动重试。

取消通过数据库标记传到工作进程，在阶段边界检查；可终止本地合成时同时处理子进程。外部付费任务可能已执行，费用继续记录。已提交的平台作品只能通过另外的撤回操作处理，本地取消不改变远端事实。

### 5.4 生成适配层约定

生成适配层统一提供 `submit`、`query` 和 `collect`，返回本项目任务编号与上游任务编号的映射、执行状态、失败阶段和产物清单。`cancel`、分段重做和中间产物复用作为明确的能力标记；上游不支持时，界面不得承诺可以执行。

提交时只传已确认脚本和已选择的素材，显式设置顺序与展示方式。生成组件的自动改写、自动发布或跨平台分发入口必须关闭，发布只能由本项目根据成片确认记录触发。收集产物后检查文件及摘要，不凭上游成功状态直接进入待确认。

独立环境中的素材不能只传本项目本地路径。阶段一须验证 API 上传、约定共享目录或 CLI 输入路径中的一种方法，记录路径映射与访问限制；生成输出复制到本项目版本目录后才视为持久化产物。

## 六 数据和业务接口

### 6.1 数据约束

| 对象 | 核心约束 |
| --- | --- |
| projects 和 script_versions | 项目引用当前草稿；脚本版本写入后不覆盖 |
| segments 和 assets | 段落绑定素材标识，源范围必须在素材时长内 |
| jobs 和 job_attempts | 保存阶段、执行租约、取消标记、上游任务编号；同一制作请求唯一 |
| artifacts 和 video_versions | 保存输入摘要、文件摘要与有效性；缺文件不能视为完成 |
| confirmations | 绑定脚本、视频、封面、文案、账号、发布方式及适用时间 |
| exports | 绑定确认记录，导出成功与平台发布分别记录 |
| publish_requests 和 publish_attempts | 上传启用后建立；账号加请求编号唯一，另查同账号同视频重复 |
| cost_entries 和 budget_reservations | 用量账本与预算预留分开，保留实际、估算、待核对标记 |
| performance_snapshots | 保存作品、观察时间、数据来源；缺指标为空 |

确认针对发布清单的规范化摘要，工作进程执行前重新比对。确认请求使用用户预览的版本编号，草稿已变化时返回冲突，避免用户在旧页面确认新内容。脚本、成片或任一发布字段变化都使当前确认失效，历史确认保留供追溯。

### 6.2 本项目接口草案

这些是本项目业务接口，不是上游已经提供的接口。初版可由 FastAPI 返回简单页面，或使用薄前端调用同一接口；先完成流程再决定是否引入独立前端工程。

| 接口 | 用途 | 关键约定 |
| --- | --- | --- |
| `POST /api/projects` | 创建主题任务 | 返回项目编号 |
| `POST /api/projects/{id}/assets` | 上传素材 | 校验类型、大小、可解码性，返回素材标识 |
| `POST /api/projects/{id}/script-jobs` | 生成脚本 | 请求编号去重，返回任务编号 |
| `PUT /api/projects/{id}/draft` | 保存文案和分镜 | 校验预期草稿版本，冲突返回 409 |
| `POST /api/projects/{id}/render-jobs` | 创建制作任务 | 绑定已确认脚本版本和参数摘要 |
| `GET /api/jobs/{id}` | 查询进度与错误 | 返回当前阶段及可执行的恢复操作 |
| `POST /api/jobs/{id}/cancel` | 请求取消 | 返回取消请求状态，不能提前宣称远端撤回 |
| `POST /api/jobs/{id}/retry` | 创建新尝试 | 仅允许明确可重试的状态 |
| `POST /api/video-versions/{id}/confirmations` | 确认成片和发布内容 | 校验检查结果、预览版本和发布清单 |
| `POST /api/confirmations/{id}/exports` | 导出发布包 | 必须是当前有效确认，返回下载标识 |
| `POST /api/projects/{id}/manual-publications` | 记录手动发布 | 保存作品链接、状态、观察时间和用户记录 |
| `POST /api/confirmations/{id}/publish-requests` | 自动上传增强接口 | 上传已启用、账号可用、确认有效才接受 |

提交长任务返回 202 与任务编号。制作、导出和发布请求都使用客户端请求编号；相同编号及相同内容返回同一记录，编号相同而内容不同返回 409。费用估算、缺素材与登录异常应有独立错误类型，界面显示具体处理动作。

## 七 成片检查和发布

### 7.1 检查门槛

| 检查项 | 初始处理 |
| --- | --- |
| 文件为空、解码失败、音轨缺失、字幕无有效条目 | 硬错误，禁止确认 |
| 时间轴引用缺失文件或源片段越界 | 硬错误，返回素材编排 |
| 字幕时间为负、开始晚于结束、超出成片范围 | 硬错误，按一帧量级容差处理尾部舍入 |
| 视频末尾未覆盖口播，差值超过 100 毫秒 | 硬错误，重新校验音频和画面长度 |
| 时长超出目标范围、字幕疑似溢出 | 提示用户修改或记录接受理由 |
| 连续黑屏超过 1 秒、连续静默超过 2 秒 | 提示人工判断，合理片段可确认通过 |
| 事实、读音、关键操作、标题封面一致性 | 用户预览检查，不能由技术检查替代 |

阈值用于发现问题，按样片调整。字幕模板设置上下左右安全边距，预览叠加平台界面参考区域；平台界面可能变化，最后仍需检查关键操作是否被遮挡。

### 7.2 发布包

确认后导出一个压缩包，包含 `video.mp4`、封面、`captions.srt`、`publish.txt` 和 `manifest.json`。发布文案包括标题、简介、话题及目标账号；清单包括确认编号、版本和文件摘要，不包含密钥、登录文件或内部原始日志。

导出完成保持发布状态为未提交。用户手动上传后录入作品结果，有公开可见证据才标为已发布；只有作品标识或提交成功提示时，记录待审核或待核对。

### 7.3 自动上传独立验收

social-auto-upload 当前主线提供登录、检查和上传 CLI，网页端不保证可直接运行，遇到二次验证仍需用户参与。集成使用独立运行环境和固定版本。[上游说明](https://github.com/dreammis/social-auto-upload)

启用前逐项检查标题、简介、话题、封面、目标账号、立即发布及结果证据。首轮只接立即发布，本地排期后置；不支持的字段在提交前显示，不能静默丢弃。创作者身份应与配置的账号标识核对，不能只相信登录文件名称。

必须通过：连续点击只生成一个请求；修改标题使旧确认失效；登录过期可恢复；提交后断网进入待核对；程序在发布中退出后不重发；平台拒绝能明确展示。账号验证和实际发布使用用户明确指定并确认的内容，开发方案本身不执行发布。

上传 CLI 正常退出只能说明执行路径结束，发布适配层还需保存可核对证据。无法核对结果时继续使用手动发布，不通过重复提交猜测成功与否。

## 八 预算和运行配置

基础版配置先集中保存内容方向、模型服务、声音、模板、制作并发、预算和产物目录，密钥单独管理。后台绑定本机地址，文件上传、模型输出和来源内容都不能直接成为 Shell 指令。

初始制作并发为 1，每日任务数为 2。现成素材任务先以 0.30 元作为变动费用预留目标，日预算 2 元；这是试运行配置，不是硬件性能或价格承诺。首次接通服务的调试费用独立记录，避免被归入正常单条成本。[成本估算与假设](../research/video-generation/cost-estimate.md)

付费阶段开始前，在事务内预留预算；完成后结算实际用量。结果不明保留预留并标记待核对，不提前释放预算。估算不足导致实际支出超过限额时，记录支出并暂停后续付费步骤；需要严格限额时同时配置供应商限额。

缓存和重试同样写用量账本。只有零付费调用的缓存复用才计为本次调用费用为零；未知费用不能填零。配音与字幕路线确定后，按包含失败和废弃成片的实际账单更新成本表。

备份数据库、确认版本及发布记录。运行日志按保留期清理；首次基础版验收需完成一次备份恢复，证明文件关联仍然有效。启动检查覆盖组件连接、FFmpeg、字体、可用磁盘空间和最近未完成任务。

## 九 开发任务和验收顺序

| 顺序 | 开发内容 | 完成条件 | 工时占位 |
| --- | --- | --- | --- |
| 1 | 固定环境，A/B/C 样片和程序调用 | 确定生成路线，保存产物、耗时和缺口 | 2～4 人日 |
| 2 | 数据表、文件目录、持久化任务与适配层 | 重启能找回任务；失败不误报成功；不重复领取 | 3～5 人日 |
| 3 | 脚本、素材范围、配音字幕和时间轴 | 教程操作顺序正确；修改能使相关产物失效 | 4～7 人日 |
| 4 | 三页工作台、检查、确认、导出与费用 | 浏览器中完成一条任务，导出确认版本 | 4～6 人日 |
| 5 | 十条试运行、故障恢复与备份恢复 | 达到样片目标，记录人工时间与真实成本 | 3～5 人日 |
| 增强 | 账号登录、上传适配、去重与结果核对 | 通过自动上传独立验收 | 3～6 人日 |

基础版暂按 16～27 人日估算，自动上传另计。数字是任务拆分后的规划占位，以一名熟悉 Python 和简单 Web 开发的开发者为假设，不含等待账号权限、资料与素材准备，阶段一完成后重新估算。若要另做复杂分镜引擎或替换字幕服务，必须先补估开发量。

关键状态和预算约束编写针对行为的测试：版本冲突、重复请求、租约失效后旧尝试不能写回、发布中断不重发、预算预留不能重复释放。集成验证覆盖实际音视频、组件退出、缺失文件和备份恢复；字体、读音、画面相关性与平台状态保留人工验收。

基础版验收不要求自动获取热点、平台数据或收入；这些能力在制作流程稳定后分别立项。

## 十 试运行记录和后续决策

每条任务记录主题、内容类别、版本、总机器耗时、资料与录屏时间、修改时间、变动制作费、失败次数和可发布结果。人工时间采用用户实际记录，不能用渲染时间替代。

十条样片完成后检查共同问题和相对手工流程的时间节省。建议将人工总耗时下降至少 30% 作为初始效率目标，按相近内容比较；三条手工基线只能提供初步判断。未达到时优先分析素材准备、读音修正或返工的占比，再决定改善模板还是减少自动化范围。

随后可试运行两周，每天发布 1～2 条。录入发布后 24 小时及 7 天可取得的指标，末批视频完成七天观察后再比较；缺失指标留空。先评价能否持续生产与内容方向是否值得继续，收入按实际结算另记。

进入下一阶段的顺序为：制作稳定 → 减少主要人工瓶颈 → 验证自动上传 → 接入一个资料来源 → 增加效果比较。某个环节验证失败时，应保留已经可用的制作与导出能力，并明确记录调整后的交付范围。
